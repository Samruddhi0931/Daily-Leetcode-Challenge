# 🟢 242. Valid Anagram

## 📌 Problem Statement

Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`, and `false` otherwise.

An **anagram** is a word formed by rearranging the letters of another word, using all the original letters exactly once.

---

## 🧾 Examples

### Example 1
```
Input: s = "anagram", t = "nagaram"
Output: true
```

### Example 2
```
Input: s = "rat", t = "car"
Output: false
```

---

## 🔒 Constraints

- `1 <= s.length, t.length <= 5 * 10^4`
- `s` and `t` consist of lowercase English letters.

---

# 🚀 Approach 1: Brute Force (Sorting)

## 💡 Idea

If two strings are anagrams:
- After sorting both strings,
- They should be identical.

---

## 🧑‍💻 Python Code

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        return sorted(s) == sorted(t)
```

---

## ⏱ Complexity

- Time: **O(n log n)** (because sorting is used)
- Space: **O(n)**

---

# 🚀 Approach 2: Optimal Solution (Hash Map / Frequency Count)

## 💡 Idea

- Count frequency of each character in both strings.
- If the frequency maps are equal → they are anagrams.

---

## 🧑‍💻 Python Code

```python
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        
        count = {}
        
        for char in s:
            count[char] = count.get(char, 0) + 1
        
        for char in t:
            if char not in count:
                return False
            count[char] -= 1
            if count[char] < 0:
                return False
        
        return True
```

---

## ⏱ Complexity

- Time: **O(n)**
- Space: **O(1)**  
  (Since only 26 lowercase letters exist, space is constant.)

✅ More efficient than sorting for large inputs.

---

# 📚 Key Takeaways

- Sorting works but costs **O(n log n)**.
- Hashing reduces time complexity to **O(n)**.
- Frequency counting is a powerful technique for string problems.
- Always check length first to optimize early.
